# 포켓몬풍 도트 UI 규칙 (battle-kr)

목표: 매끈한 모던 UI(둥근 사각형·부드러운 그라데이션·흐린 그림자)가 아니라, 3~5세대 포켓몬 게임처럼 **픽셀 격자에 딱 맞는 창과 버튼**.
배경(배틀 필드·메뉴 배경 그림)과 포켓몬 그림은 손대지 않는다. 디자인을 크게 바꿀 때는 먼저 시안(스크린샷)을 보여 주고 확인받는다.

## 1. 모서리: 매끈한 곡선 금지, 픽셀 계단
- `border-radius` 로 모서리를 둥글리지 않는다 (0). 둥근 느낌은 **픽셀 계단**으로 낸다.
- 큰 창·버튼의 테두리는 `battle-kr/scripts/pixring.py` 가 만드는 9분할 테두리 그림을 쓴다.
  - 진한 외곽선 1칸 + 안쪽 테두리 1칸, 한 칸 = 2px, 모서리 반지름 6칸(큰 버튼·창)·2칸(HP 상자·작은 표시)
  - 같은 계단 모양의 `clip-path`(`--clip4`, `--clip2`)로 요소를 잘라 모서리 밖을 비운다.
  - 색 조합이 새로 필요하면 `pixring.py` 의 `rings` 에 추가하고 다시 실행해 `src/style.css` 의 `:root` 변수 블록을 바꾼다. 손으로 SVG 를 고치지 않는다.
- 작은 표(타입·분류·상성 배지)는 모서리 한 칸만 깎는 `clip-path` 로.

## 2. 그림자·입체감: 흐림 없이
- `box-shadow` / `text-shadow` / `drop-shadow` 의 흐림(blur) 값은 항상 0.
- 입체감은 NES.css 방식: `::after` 에 **안쪽 그림자** — 오른쪽·아래 한 칸 어둡게, 왼쪽·위 한 칸 밝게. 누르면 반대로 뒤집는다.
- 색은 부드러운 그라데이션 대신 **3~4단 색 띠**(`linear-gradient` 의 딱 끊긴 구간). 띠는 테두리까지 포함한 요소 전체 기준(`background-origin: border-box`).

## 3. 픽셀 격자
- 테두리 두께·여백·간격·이동 거리는 한 칸(2px)의 배수로.
- 도트 그림·테두리 그림에는 `image-rendering: pixelated`.
- 크기를 바꿀 때도 계단 모서리가 늘어나지 않게 9분할(`border-image-slice`)을 쓴다 — 가운데만 늘어나고 모서리 픽셀은 그대로.

## 4. 버튼 상태 3단계
- **기본**: 위 한 칸 밝은 줄·아래 한 칸 어두운 줄(입체).
- **가리킴**(마우스 `:hover`, 키보드 `:focus-visible`): 버튼 안 왼쪽에 검은 도트 삼각형 커서 `▶` (흰 테두리 1칸). 터치 화면에는 가리킴이 없으므로 이것에만 기대지 않는다.
- **누름**(`:active`): 요소 전체가 오른쪽·아래로 한 칸(2px) 이동, 입체 그림자를 뒤집어 눌린 모양.
- 고를 수 없는 버튼은 회색조로 흐리게 하되 글자는 읽히게.

## 5. 글꼴
- 한글은 앱에 들어 있는 **갈무리(Galmuri11)** 만 쓴다 (`src/fonts`). 다른 글꼴을 추가하지 않는다.
- 글자 그림자는 흐림 없이 오른쪽 아래 한 칸(`2px 2px 0`). 밝은 바탕의 흰 글자는 진한 외곽선(사방 1px)을 두른다.

## 6. 하지 말 것
- 실제 게임(하트골드 등)의 그래픽 파일을 가져다 쓰지 않는다. 구성·분위기만 참고하고 그림은 CSS·스크립트로 새로 그린다.
- 매끈한 둥근 모서리, 흐린 그림자, 유리 효과(blur·반투명 겹침), 부드러운 그라데이션.

## 확인 방법
- `node battle-kr/build.mjs` 뒤 Playwright 로 배틀 화면(명령·기술·교체·더블 대상)을 휴대폰 크기(Pixel 7, deviceScaleFactor 2)로 찍고, 모서리 부분을 잘라 확대해 계단·테두리 두께·색 띠 어긋남을 직접 본다.
